# نظام متكامل: مبيعات ومشتريات ومخزون ومحاسبة + صيانة المعدات
معدات ورش ومصانع، أدوات سلامة، حديد، وقسم خدمات صيانة الجملونات والهناجر. فرعان (بورسودان / الخرطوم).

الوحدات: الأصناف + مخزون لكل فرع + تحويلات بين الفروع، فواتير بيع وشراء (نقدي/آجل)، متوسط التكلفة المرجّح،
العملاء والموردون وكشوف الحساب، الخزائن والبنوك وسندات القبض والصرف، المصروفات، أوامر خدمة الصيانة (خامات من المخزن ثم فوترة)،
تقارير: قائمة الدخل، الربح حسب القسم، مقارنة الفروع، قيمة المخزون.

## التشغيل
1. PostgreSQL + نسخ `.env.example` إلى `.env` (DATABASE_URL, ADMIN_PASSWORD)
2. `npm install && npm run db:push && npm run seed` (seed اختياري)
3. `npm run dev` أو `npm run build` ثم `node .next/standalone/server.js` (انسخ `.next/static` بجانبه) — أو استخدم Dockerfile على Coolify.
خلف HTTP بدون HTTPS اضبط INSECURE_COOKIE=1.

## المستخدمون
أول دخول: المستخدم `admin` وكلمة المرور = `ADMIN_PASSWORD` (يُنشأ حساب المدير تلقائياً). بعدها أضف المستخدمين من صفحة «المستخدمون».
- **مدير:** كل الصلاحيات وكل الفروع.
- **موظف فرع:** يعمل على فرعه فقط (بيع/شراء/مخزون/مصروفات/أوامر خدمة)، ولا يرى الإعدادات والتقارير والمستخدمين.
اضبط `SESSION_SECRET` بقيمة عشوائية طويلة في الإنتاج. رأسية الفاتورة المطبوعة من الإعدادات ← بيانات الشركة.

## صيانة المعدات (مدمجة)
معدات الشركة (أصول) لكل فرع/قسم، الصيانة الوقائية الدورية، أوامر العمل (وقائية/علاجية/طارئة)، الفنيون. قطع الغيار تُصرف من مخزون الفرع نفسه (نفس الأصناف والتكلفة)، وتقرير تكلفة صيانة كل معدة ضمن التقارير.

## الفروع والأقسام
من الإعدادات يمكن إضافة فرع أو قسم مستقل في أي وقت. لكل وحدة مخزونها وفواتيرها وخزائنها ومعداتها وتقاريرها ومستخدموها.

## المرتجعات وسجل النشاط والعزل بين الفروع
- **المرتجعات:** من صفحة الفاتورة زر «مرتجع مبيعات/مشتريات». يعيد/يُخرج المخزون، ويُخفّض حساب العميل أو المورد، ويحتسب الخصم تناسبياً، ويسمح برد نقدي بقدر المدفوع الزائد فقط. المبيعات والتكلفة في التقارير صافية بعد المرتجعات.
- **سجل النشاط** (للمدير): من فعل ماذا ومتى (فواتير، سندات، تسويات، إلغاء، مرتجعات، مستخدمون، دخول ومحاولات فاشلة).
- **العزل:** موظف الفرع لا يفتح فواتير أو أوامر أو معدات فرع آخر ولو بالرابط، ولا يستخدم خزائن فرع آخر.

## تكلفة الاستيراد، التسعير بالدولار، الدفعات المرحلية
- **تكلفة الاستيراد الواصلة:** في فاتورة الشراء أدخل حتى 4 بنود (شحن، جمارك، رسوم ميناء، تخليص) وخزينة الدفع؛ تُوزَّع على الأصناف بنسبة قيمتها وتدخل في متوسط التكلفة، ويظهر سعر المورد والتكلفة الواصلة في الفاتورة.
- **التسعير بالدولار:** الإعدادات ← سعر الصرف ← «حفظ وتحديث الأسعار»؛ لكل صنف له «سعر بالدولار» يُعاد سعره المحلي = الدولار × السعر. تعديل الأصناف من قائمة الأصناف (للمدير). يظهر تحذير أحمر في فاتورة البيع عند السعر الأقل من التكلفة.
- **الدفعات المرحلية لأوامر الخدمة:** من صفحة الأمر (قالب 30/40/30 أو دفعات مخصصة). تُفوتر الدفعات تباعاً بعد الاعتماد، والأخيرة بعد «منجز» وتتحمل كامل التكلفة.

## تأجير المعدات
- حدّد سعر التأجير اليومي لكل معدة (من صفحة المعدة)، ثم أنشئ عقداً من «الخدمات ← تأجير المعدات» (عربون اختياري يدخل الخزينة).
- المعدة تتحول إلى «مؤجرة» ولا يمكن تأجيرها مرتين. العقود المتأخرة عن الإرجاع تظهر بالأحمر وفي لوحة التحكم.
- عند الإرجاع: المدة × السعر + رسوم التلف → تُصدر فاتورة بيع تلقائياً بعد خصم العربون. إن وُجد تلف أو اختيرت «تحتاج صيانة» تتحول المعدة إلى «صيانة» ويُفتح أمر عمل تصحيحي.
- يظهر إيراد التأجير في التقارير تحت «تأجير معدات» وفي صفحة كل معدة.
- ملاحظات: بنود التأجير بتكلفة صفر (الإهلاك غير محسوب)، العربون الزائد عن الإجمالي يبقى رصيداً للعميل، ولا يمكن إلغاء عقد استُلم عليه عربون.

## ميزات الإضافة الأخيرة
- **عروض الأسعار** (`/quotes`): بنود من المخزون أو بنود حرة (عمالة/خدمة)، طباعة، وتحويل بضغطة إلى فاتورة بيع تخصم المخزون.
- **تقادم الديون** (`/reports/aging`): عملاء/موردون حسب 0–30 / 31–60 / 61–90 / +90 يوماً (الدفعات تسدّد الأقدم أولاً).
- **التنبيهات** (`/alerts`): ديون متأخرة، معدات مؤجرة متأخرة، شيكات مستحقة، نقص مخزون، صيانة وقائية، عروض منتهية. زر واتساب يفتح المحادثة برسالة جاهزة (الإرسال يدوي؛ الإرسال الآلي يحتاج WhatsApp Business API).
- **الباركود**: حقل باركود للأصناف والمعدات، مسح بقارئ USB (يعمل كلوحة مفاتيح) داخل الفواتير والجرد، وطباعة الملصقات من `/labels`.
- **الجرد الفعلي** (`/stocktakes`): لقطة بالنظام، إدخال/مسح الكميات، ثم اعتماد يسوّي الفروقات ويسجلها في حركة المخزون.
- **الإهلاك**: قسط ثابت يومي من العمر الإنتاجي وقيمة الخردة؛ القيمة الدفترية وصافي عائد التأجير في صفحة المعدة وتقرير `/reports/assets`، وسطر «إهلاك الأصول» في قائمة الدخل (للعرض ولا يدخل في الدفاتر).
- **الشيكات** (`/cheques`): مستلمة وصادرة؛ لا تؤثر على الأرصدة إلا عند التحصيل/الصرف (ويمكن ربطها برقم فاتورة)، والمرتدة تُسجَّل دون قيد.
- **عملات الفواتير**: فواتير البيع والشراء بالدولار بسعر صرف يُحفظ مع الفاتورة؛ تُخزَّن بالمحلي وتُعرض بالمكافئ. الخزائن والأرصدة تبقى بالعملة المحلية.
- **واجهة الفنيين** (`/field`) للجوال، وقائمة علوية مضغوطة للشاشات الصغيرة.

## الجوال
- **PWA:** افتح الموقع من متصفح الجوال (Chrome على أندرويد أو Safari على iOS) ← «إضافة إلى الشاشة الرئيسية» فيعمل بملء الشاشة بأيقونة. يتطلب HTTPS (يوفره Coolify).
- **مسح الباركود بالكاميرا:** زر «📷 كاميرا» بجانب خانة الباركود في الفواتير والجرد. يتطلب HTTPS وإذن الكاميرا.
- أسطر الأصناف في الفواتير تُعرض كبطاقات على الشاشات الصغيرة، والقائمة تتحول إلى «☰ القائمة» علوية.
- لا يعمل دون اتصال بالإنترنت.

## النشر على Vercel + Supabase
1. Supabase: أنشئ مشروعاً، ثم Connect ← انسخ **Session pooler** (5432) لإنشاء الجداول، و**Transaction pooler** (6543) للتطبيق.
2. من جهازك: `DATABASE_URL=<session pooler> npx drizzle-kit push`
3. Vercel: Import المستودع. المتغيرات: `DATABASE_URL` (Transaction pooler)، `ADMIN_PASSWORD`، `SESSION_SECRET`. ثم Deploy.
4. فعّل RLS على الجداول في Supabase ولا تستخدم الـ Data API.

## النسخة التجريبية (Demo)
1. أنشئ مشروع Supabase مستقلاً للعرض، وأنشئ الجداول (`supabase-schema.sql` في SQL Editor أو `drizzle-kit push`).
2. املأه ببيانات وهمية (يرفض العمل إن كانت القاعدة غير فارغة): `DATABASE_URL=<session pooler> DEMO_PASSWORD=<كلمة> npx tsx src/db/seed-demo.ts`
3. على Vercel (مشروع منفصل): `DATABASE_URL` (6543) + `SESSION_SECRET` + `ADMIN_PASSWORD` + **`DEMO=1`** + `DEMO_PASSWORD`.
4. يظهر شريط «نسخة تجريبية» وبيانات الدخول في صفحة الدخول. المستخدمان: `demo` (مدير) و`portsudan` (موظف فرع).
- لإعادة ضبط البيانات: أفرغ الجداول (Reset من SQL Editor: `drop schema public cascade; create schema public;` ثم أعد إنشاء الجداول وشغّل السكربت).

## الواجهة (تحديث)
- القائمة الجانبية 6 أقسام فقط (الرئيسية، المبيعات، المشتريات، المخزون، المعدات والصيانة، التقارير والإعدادات)، وبداخل كل قسم تبويبات أفقية. موظف الفرع لا يرى عناصر المدير.
- بحث شامل في الأعلى (اضغط `/`) يشمل الأصناف والعملاء والفواتير وعروض الأسعار والمعدات وأوامر العمل والتأجير، ويحترم عزل الفروع.
- زر «+ جديد» لإنشاء فاتورة أو عرض سعر أو تأجير أو بلاغ عطل بسرعة.
- الجوال: شريط سفلي (الرئيسية، المبيعات، المخزون، المعدات، المزيد) وشاشة «المزيد» لكل الأقسام.
- لوحة التحكم: 4 مؤشرات رئيسية، رسم بياني 6 أشهر، بطاقة «يحتاج انتباهك»، والخط Cairo مضمّن (يعمل دون إنترنت).
- واجهة عصرية: لون أزرق `#1D4ED8`، أيقونات خطية (Lucide)، قائمة جانبية نحيفة تتمدد عند التمرير، شارات ملونة لحالة الدفع، ترحيب ومخططات مصغّرة في لوحة التحكم، ووضع داكن (زر القمر في الأعلى، يُحفظ في المتصفح).


> **هذه نسخة تجريبية:** وضع العرض مفعّل دائماً (شريط تنبيه + بيانات الدخول). أنشئ الجداول ثم `npm run seed:demo` (متغير `DEMO_PASSWORD` اختياري، الافتراضي demo1234). المتغيرات على Vercel: `DATABASE_URL` و`SESSION_SECRET` و`ADMIN_PASSWORD`.
